# P0：可靠执行、诊断与构建发布设计

状态：待用户评审。属于 [完整迭代目标](2026-10-15-reliability-roadmap.md) 的第一阶段，不取代 P1/P2。

## 1. 组件边界

- `diagnostics`：可序列化的阶段、错误类别、HTTP 状态、脱敏摘要、重试建议及可用性等级。
- `operation`：取消标记、进程互斥、事务日志、快照校验、提交与显式回滚；退出前返回恢复结果。
- `http/core_api/mihomo`：传输证据与类型化错误，不决定 UI 文案和进程退出。
- `checker`：初筛与候选验证，返回报告；不直接同步客户端记忆。
- `appstate`：只在成功提交后写入起始订阅对应的选择记录，不能在操作期间重新读取另一个订阅再写入。
- `main/ui`：参数、调用和展示；取消和错误需要先经过事务收尾，再退出。

只提取本轮必须共享的执行边界，现有客户端发现、命名管道身份验证、节点信息解析继续复用。

## 2. 切换事务

`fix/use/watch` 的每次修改操作采用同一流程：

1. 获取当前 Windows 用户的 ProxPilot 修改互斥锁；锁冲突立即返回 busy，不发出 PUT 或写注册表/第三方数据库。采用每用户全局修改锁，因为系统代理是共享资源；只读命令仍可并发。
2. 快照客户端身份、订阅 ID（适用时）、策略组的直接选择、目标测试配置、相关系统代理值；启动 watch 不持有整段运行的锁。
3. 首次修改前原子写入不含凭据的恢复日志。原选择不可读时拒绝开始切换，不能用“未知”作为回滚目标。
4. 每次 PUT 前后验证服务端身份、策略组存在性和直接选择。当前选择必须等于操作已知的上一次写入；被 GUI/另一个程序改变时中止，报告冲突，不覆盖新选择。
5. 候选实测每次使用新连接；用户取消停止领取新任务并取消可取消的网络等待。
6. 最优候选需要最终验证和选择回读。只有最终确认通过，才提交事务并同步起始订阅的记忆。`PassIpOnly` 可作为明确标注的低置信度备选，不能覆盖已有网页验证通过的候选。
7. 所有候选失败、最终切换/确认失败、取消时，明确执行恢复并回读。恢复前同样检查身份/订阅/当前选择；存在外部修改则保留外部状态，报告恢复被跳过的原因。
8. 恢复失败保留日志并返回非零，不输出“已恢复”。成功提交或恢复后清理日志。第三方数据库写入失败单独报告，不能把内核已提交说成切换失败。

PUT 前日志先记录待写目标；若响应丢失，回读可能仍为旧选择或已经是本次目标，这两者都属于已知状态，不能把“写入成功但响应丢失”误判为用户改动。出现第三个选择则按外部冲突处理。日志不存 API secret，重启后凭据从当前客户端重新获取；恢复载荷用当前用户的 Windows 数据保护加密，原子替换写入，避免原节点名或路径中的私密内容以明文落盘。

内核没有比较并交换接口，无法对 GUI 的并发修改提供跨进程原子保证。设计保证检测到的外部变化不会被恢复操作覆盖，并用每次修改前后回读缩小竞争窗口；实现和文档不得宣称能识别所有瞬间切换或 ABA 变化。

`use` 也在验证后提交；验证失败恢复原选择并返回 2。`fix` 的最终验证进入事务内部，不再在返回成功后额外打印一个不影响退出码的警告。回滚的是原来的直接选择，可为合法嵌套组，不将其错误替换为猜测的最终节点。

恢复日志仅在下次修改运行中处理：验证客户端、订阅和上一次写入仍匹配后尝试恢复；`scan/diagnose` 只报告待恢复状态。日志损坏、旧客户端实例或节点已消失时不猜测；列出可人工处理的信息。

## 3. 系统代理与取消

保留 `check/fix/watch` 修复系统代理的能力。自动修复也获取修改锁；`check --dry-run` 不修改。系统代理和节点变化在同一操作中发生时，事务失败可恢复本次操作改变的代理值，但仅在它们仍等于本次写入值时恢复；保留绕过规则和操作外的新值。失败的半写入也必须报告。SOCKS 出口仍不被写为 Windows HTTP 代理。

用 Windows 控制台处理器设置取消标记，处理器中不执行网络或数据库操作。控制循环、扫描任务领取、候选验证和 sleep 等待都检查标记；取消停止新工作，等待已有不可立即中断的系统调用的有界超时，并在正常控制流中收尾。Ctrl+C 退出码为 130。不能依靠 Drop 中吞掉错误来证明恢复成功。

## 4. 故障模型

错误记录包含 `code`、`stage`、`http_status`（可空）、`retryable` 和脱敏说明。

至少区分：参数/URL、客户端不可用、身份冲突、控制接口鉴权、控制接口 HTTP 错误、控制接口超时、代理连接失败、连接/整体超时、TLS、已确认的 DNS、响应传输/截断、网站 HTTP 拒绝、用户取消、修改锁冲突、回滚失败。

依赖未提供足够证据时使用 `transport_unknown`，不能靠一条模糊错误字符串断言远端 DNS 或 IP 风控。保留真实 HTTP 403/429/5xx，HTTP 状态缺失使用 null，不构造 HTTP 0。401 交叉检查仍仅标记 `ip_only`。OpenAI URL 判定按解析后的精确主机或合法子域边界，不匹配 `openai.com.example.org`。

错误的 URL、鉴权头和第三方响应体不直接打印。类型化报告为 P2 提供稳定输入，P0 的默认输出仍为现有中文文本。

## 5. 构建发布

- 固定开发/release 工具链为本机已验证的 Rust 1.99.0；保持并在 CI 验证最低 Rust 1.98.0，不能未测试就降低最低版本。
- CI 使用 `windows-2025-vs2026`，输出 Rust、MSVC linker 和 SDK 信息，校验预编译清单；检查工具集不早于 manifest 要求。工具集要求无法满足时明确失败。
- CI 从干净 checkout、独立 Cargo target 目录构建，运行离线模拟内核测试和 release smoke test；原生依赖消费阶段不调用 CMake/NASM/libclang。
- 若实际验证表明原生库含要求精确版本的 `/GL`，需以兼容的无 `/GL` 设置重新生成整套库/绑定及 manifest 并验证，不能跳过失败。
- `build.bat` 使用锁定依赖，检查构建、产物定位和复制返回值。配置了 target triple/CARGO_TARGET_DIR 时准确定位本次产物，不优先误选旧 target/release 文件。
- 提供 UTF-8/ASCII 提示的 PowerShell 打包脚本，bat 仅作入口。默认只验证和打包；发布需要显式发布模式，不暗中 `git add -A` 或代为提交。
- 发布前检查工作区、版本/CHANGELOG、tag、gh 身份、测试、依赖和构建。任何一步失败停止；不通过管道丢失原始退出码。
- 打包产物附 SHA256、版本和提交信息、许可证；Release 默认草稿。发布脚本不得在失败后继续上传，重试不能静默覆盖已有同名 tag 或 Release。

P0 验收包括干净 runner 的真实运行日志。仅添加 YAML 不能称为“其他电脑已能编译”。不以运行全量 live 网络测试作为每次提交的必需条件。

## 6. 必测场景

本机模拟 HTTP/命名管道内核验证成功提交、候选全失败、最终 PUT 失败、最终验证失败、回滚 PUT/回读失败、原选择为嵌套组、节点/订阅改变、用户在测试中手动切换、记忆库锁定。每个场景断言请求序列、最终状态、持久化时机和退出码。

子进程验证两次修改互斥、只读扫描仍可运行、Ctrl+C 停止派发及正常恢复、互斥锁随进程结束释放、恢复日志的读取与身份校验。用测试注册表子键而非真实 Internet Settings 做代理快照测试。

传输测试注入代理拒绝连接、TLS 证书错误、超时、响应截断、401/403/429、坏 JSON 和包含假 OpenAI 域名的 URL。脚本用替身 cargo/git/gh 注入失败，确认不会继续 push/upload，不包含真实发布动作。
