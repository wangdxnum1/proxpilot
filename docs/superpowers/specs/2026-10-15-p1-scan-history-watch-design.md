# P1：扫描调优、历史评分与守护防抖设计

状态：用户已批准；按阶段实施。依赖 [P0](2026-10-15-p0-reliable-execution-design.md) 的报告、取消和事务；属于 [完整目标](2026-10-15-reliability-roadmap.md)。

## 1. 可控扫描

新增参数及初始默认值：

| 参数 | 默认 | 边界 |
|---|---|---|
| `--concurrency N` | 未指定时采用自适应上限 | 显式值 1–256；实际不超过节点数 |
| `--probe-timeout-ms N` | 4000 | 100–120000 |
| `--verify-timeout-ms N` | 12000 | 100–120000；浏览器候补共享整体时间预算 |
| `--retries N` | 1 | 0–3，表示首次请求以外的重试次数 |

显式并发为固定上限；自动模式上限为 `min(CPU×2, 32, 节点数)`。2026-10-16 性能修订：从计算出的上限启动，使用连续补位的有界工作线程；单个节点结束即可派发下一个，不等待整批最慢节点。按已完成节点的采样窗口统计：可重试传输失败达到一半时并发减半，最低 1；连续两个窗口无可重试错误时加 2，直到上限。采样窗口大小等于窗口开始时的目标并发，窗口只用于统计，不阻塞派发；最后不足窗口不做自适应决策。降并发时不打断已有请求，等待在途任务自然回落后再补位。JSON 的 `probe.windows` 保留字段名，现记录初始及调整后的并发目标。连接取消和全局控制 API 故障不用于降低单个节点评分。

仅重试可重试的初筛传输错误/超时，退避 200ms、400ms、800ms，可取消。HTTP 拒绝、坏参数、鉴权或身份冲突不重复尝试。真实网站验证仍使用 `--samples`，不暗中把失败采样重试成全部成功。输出总节点数、唯一完成数、重试次数和实际并发；重试不增加完成节点数。控制接口整体失败时应明确报环境错误，不显示“全部节点不可达”。

## 2. 历史存储

独立数据库 `%APPDATA%/ProxPilot/history.sqlite3`，不复用第三方客户端数据库。schema 版本化，按客户端/配置源身份、可确定的订阅 ID、组、节点及测试目标隔离；目标完整 URL 仅保存不可逆指纹，不保存 query/userinfo。匿名 API 以规范化 endpoint 指纹隔离。命名管道实例改变时以已确认的配置源/客户端身份延续，身份不明时不合并。

记录时间、探测/网页实测阶段、耗时、可用性等级和错误类别；不保存响应体、Cookie 或访问凭据。初筛可达不能计为网页验证成功。保留最近 30 天，最多 10000 条测量，按时间清理。使用短事务和有界 busy timeout；数据库锁定/只读/损坏不妨碍本次扫描，报告历史不可用，禁止悄悄覆盖损坏数据库。

`history` 展示最近结果和评分依据，`history clear` 明确清理本工具记录。默认 scan 延迟排行仍按本轮测量排序；历史用于优选和额外说明，不替换实时延迟，也不让过期测量冒充本轮结果。

## 3. 候选评分

倍率过滤始终先于网络请求。当前本轮网页验证通过优先于 `ip_only`，后者优先于失败；历史评分不能跨越这个等级。数据少于 3 次网页实测时标记样本不足，使用中性成功率/波动先验，不将“未测”当失败。

同一等级内，综合分为 0–100：

- 成功率权重 50%，使用近 30 天网页实测及 Laplace 平滑 `(成功次数+1)/(总次数+2)`；样本不足取 0.5。
- 延迟权重 25%，使用网页成功实测中位数，归一化 `1/(1+毫秒数/500)`；无历史成功值时用本轮成功实测。
- 稳定性权重 15%，`1/(1+MAD/max(中位数,1))`；不足 3 次成功实测取 0.5。
- 成本权重 10%，已知倍率 `1/(1+倍率)`；未知为 0，但不越过本轮验证等级。

`ip_only` 没有成功网页耗时且没有历史成功耗时时，延迟分取中性值 0.5，不用零延迟或无穷耗时参加数值运算。分数计算与排序只接受有限数值。

分数相同先比较本轮实测耗时，再比较节点名，保证确定性。候选仍须在本轮验证，不能仅靠历史直接切换。数据过期按无历史处理。展示评分组成和样本数，避免把人为权重包装成线路客观质量。

## 4. 守护状态机

保留默认故障修复语义和两次失败确认（间隔 5 秒）。新增可配置值：最短正式切换间隔 120 秒、失败节点冷却 600 秒、用户手动选择保护 900 秒。保护计时与周期调度使用单调时钟；跨进程记录只用于历史展示，不依赖不可信墙钟延长锁。

- 只有 `--optimize` 才在启动或 reopt 周期主动优选。
- 主动优化候选需与当前节点按相同采样规则验证；同等级候选要求综合分提升至少 5 分，同时网页延迟降低至少 20% 且至少 100ms，才正式切换。
- 更高验证等级可优于低置信度当前节点；当前明确故障时允许绕过最短间隔，但不能绕过客户端身份、倍率或事务校验。
- 冷却节点不被反复验证。全部候选均在冷却时报告下一次可尝试时间，不静默清除冷却。
- 每轮比较上轮选择与本轮实时选择。发现操作外变化后，采用用户新选择并重置主动优化计时；保护期内不主动优选，故障时仍可在明确失败确认后修复。
- 订阅/组切换重置对应状态，不把旧配置的冷却或当前节点应用到新配置。
- 控制接口故障不记为全部节点失败；进入等待恢复状态。所有周期、复测和退避 sleep 可取消。
- 候选测试过程的临时切换由 P0 事务管理；无足够收益时恢复原节点，不能把“决定不优化”留在最后一个候选。

## 5. 验收

模拟内核记录并发峰值和请求序列，测试固定/自动并发、上下界、重试计数和鉴权不重试、超时生效、取消不再派发。

临时数据库和可控时钟测试历史分层、跨客户端/订阅/目标隔离、30 天与10000条清理、锁定/损坏降级、评分公式、冷启动和过期记录。历史成绩好但本轮失败的节点必须被拒绝。

守护测试覆盖默认不主动优选、启动/周期优化、收益不足恢复、短期抖动、冷却耗尽、手动切换保护、保护期内故障、配置更新、API 断开以及取消周期等待。测试不等待真实的分钟级时间。
