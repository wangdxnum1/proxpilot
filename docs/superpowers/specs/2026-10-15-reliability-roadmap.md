# ProxPilot P0 / P1 / P2 迭代总设计

日期：2026-10-15。状态：用户已批准架构及详细设计，授权自主采用推荐选项；按 P0 → P1 → P2 实施中。

## 用户目标与交付边界

落实此前列出的全部七个方向：切换与回滚、故障诊断、构建发布、扫描调优、历史评分、守护防抖、结构化输出及终端交互。保留 Windows x64 单文件 CLI，按 P0 → P1 → P2 分阶段交付，每阶段都有独立计划、回归测试和可执行文件。完成一个阶段不代表总目标完成。

本轮不制作 GUI、不增加后台服务、不自动启用第三方客户端控制接口、不修改订阅的托管属性。BoringSSL 浏览器指纹能力、客户端身份校验、按订阅隔离的记忆同步、倍率限制、当前节点识别和 scan 的颜色/列布局均保留。

## 已核实的缺口

| 方向 | 源码证据 | 影响 |
|---|---|---|
| 切换事务 | `src/checker.rs` 的 `fix_flow` 忽略恢复原节点的返回值，最终切换失败也没有统一恢复出口 | 无法可靠区分恢复成功与失败 |
| 最终验证 | `src/main.rs` 的 `cmd_fix` 最终确认失败后仍返回 0；`cmd_use` 验证前同步选择记忆 | 失败被报告为成功，坏节点被持久化 |
| 故障分类 | `verify_access` 把请求错误变成 `(0, 99.0)`；`probe_delay` 把错误丢弃为 None | DNS/TLS/超时/API 故障难以定位 |
| 扫描调优 | 并发固定为 CPU×2；初筛超时 4000ms；实测整体超时 12s | 不同网络环境无法调整，无法评估误判 |
| 守护策略 | `cmd_watch` 有一次 5s 复测，但无节点冷却、手动选择保护和优化收益门槛 | 重复尝试故障节点，可能覆盖用户选择 |
| 发布流程 | `release.bat` 使用 `git add -A`；推送经管道过滤且不检查错误；`build.bat` 不检查复制退出码 | 可能误收文件、失败后继续发布或交付旧 exe |
| 输出架构 | 命令执行、打印和退出交织在 main/checker/appstate 中 | JSON 与交互模式无法可靠复用业务结果 |

## 方案选择

采用用户已确认的渐进方案：沿用现有 HTTP/TLS、Windows API、SQLite 依赖，逐步提取结果模型与有副作用的执行边界。文本、JSON 与交互界面消费同一批业务结果，不能各自实现一套切换或倍率判断。

未采用整体重写：会扩大客户端兼容与节点判断的回归范围。仅增加 CLI 参数和零散提示也不足以处理异常恢复及干净 JSON，因此 P0 必须先建立事务、取消和类型化结果。

## 三阶段交付

### P0：可靠执行与构建发布

详细设计：[P0 设计](2026-10-15-p0-reliable-execution-design.md)。

- 验证后提交选择；异常、取消或最终确认失败时明确恢复结果。
- 修改操作互斥，检查客户端身份、订阅及用户外部切换。
- 保留结构化错误和真实 HTTP 状态，不能再伪造 HTTP 0 或推断“整批 IP 被风控”。
- 固定工具链，干净 Windows CI、内置依赖校验、失败即停的打包发布与 SHA256。

### P1：可控扫描与稳定优选

详细设计：[P1 设计](2026-10-15-p1-scan-history-watch-design.md)。

- 并发、超时、重试可配置；自适应并发必须有明确上限并输出实际使用值。
- 保存分层历史；实时验证结果优先于历史评分；倍率过滤在网络请求之前生效。
- 默认守护仍只在故障时修复；主动优化有收益门槛、冷却和手动切换保护。

### P2：JSON、诊断报告与终端交互

详细设计：[P2 设计](2026-10-15-p2-output-and-interaction-design.md)。

- 所有操作命令可返回稳定 JSON；watch 使用逐行事件，stdout 不混入 banner/spinner。
- 诊断报告只读、默认脱敏，可在内核未启动时生成部分结果。
- 交互入口可筛选、分页、查看详情、确认切换；复用 P0/P1，不另写切换逻辑。

## 公共约束

1. 平台保持 `x86_64-pc-windows-msvc`，静态 CRT、SQLite、BoringSSL。
2. 显式 `--client` / `--api` 优先，auto 不跨客户端回退，watch 固定启动客户端。
3. `scan/nodes/info/clients/diagnose` 和所有 `--dry-run` 不改系统代理、节点或第三方选择记忆。本工具自己的诊断/测量记录属于独立本地状态，须说明来源。
4. 未知/冲突倍率不被当作1倍率；有 `--max-rate` 时不放宽限制。回滚可恢复不合规原节点，因为其目的是恢复用户原状态。
5. 仅 IP 检查通过保持独立状态，不能显示为网页访问通过。精确解析目标 URL 主机，禁止以字符串包含关系认定 OpenAI 站点。
6. 外部请求不得禁用证书验证，不打印或持久化密码、UUID、secret、Cookie、订阅 URL。
7. 默认文本输出保持当前已确认颜色、列对齐、完整1倍率清单和当前节点独立展示。
8. 正常成功退出 0；环境/参数错误 1；网站验证失败 2；取消 130。JSON 中保留更细的错误码。
9. 不能承诺强制杀进程、断电后立即回滚；保留待恢复日志，在下次有修改意图的运行中验证身份、订阅和现状后处理。

## 构建设计的外部依据

- [GitHub runner-images](https://github.com/actions/runner-images)：当前提供 `windows-2025-vs2026`；使用具体标签，避免 `windows-latest` 漂移。
- [该镜像的软件清单](https://github.com/actions/runner-images/blob/main/images/windows/Windows2025-VS2026-Readme.md)：作为候选 CI 环境，实际链接器版本由 job 输出并校验。
- [Microsoft MSVC 二进制兼容规则](https://learn.microsoft.com/en-us/cpp/porting/binary-compat-2015-2017)：链接器不能早于输入库工具集，带 `/GL` 的静态库还要求更严格的工具集匹配。CI 成功前不扩大兼容承诺。
